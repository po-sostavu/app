## Что изменилось

### Caddy

Версия сервера осталась 2.11.9. `apps/pwa/Dockerfile` собирает бинарник из `infra/caddy` и помещает его в закреплённый по digest официальный runtime. Набор стандартных модулей сохранён. Версии зависимостей и контрольные суммы находятся в `go.mod` и `go.sum`.

| Зависимость                         | Закреплённая версия                     | Исправление                                                                                                |
| ----------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `golang.org/x/net`                  | `v0.62.0`                               | [GO-2026-6860](https://pkg.go.dev/vuln/GO-2026-6860), [GO-2026-6866](https://pkg.go.dev/vuln/GO-2026-6866) |
| `golang.org/x/crypto`               | `v0.58.1-0.20261009181718-2f1f834330b2` | [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932)                                                       |
| `go.step.sm/crypto`                 | `v0.92.0`                               | Переход с `go-jose/v3` на исправленную ветку v4                                                            |
| `github.com/smallstep/certificates` | `v0.30.3-0.20261105213751-6d5a251fbe01` | Совместимость с новой криптобиблиотекой                                                                    |
| `github.com/smallstep/cli-utils`    | `v0.13.0`                               | Совместимость с новой криптобиблиотекой                                                                    |
| `github.com/go-jose/go-jose/v4`     | `v4.1.9`                                | Замена неподдерживаемой ветки v3                                                                           |

Две зависимости закреплены на официальных коммитах до следующего тегированного релиза. Изменения Smallstep уже [приняты upstream](https://github.com/smallstep/certificates/commit/6d5a251fbe010383c93ead1ab451a329986b80ca). Простое обновление только `go.step.sm/crypto` несовместимо с прежним Smallstep, поэтому версии обновлены вместе. Локальных патчей стороннего кода нет.

Готовый официальный Caddy 2.11.9 ещё содержит прежние библиотеки. Поэтому замена тега базового образа не закрывала находки. Сборка остаётся частью существующего Docker job CI. Компилятор и исходники не попадают в runtime.

### PostgreSQL

PostgreSQL остался на 18.6 с прежним digest базового образа, entrypoint и расположением данных. Заменён только `gosu`: исходники [1.20](https://github.com/tianon/gosu/releases/tag/1.20) проверяются по SHA-256 и собираются Go 1.27.3 с `golang.org/x/sys v0.44.0`. В этой версии `gosu` уже используется исправленный парсер `moby/sys/user v0.4.1`.

Сборка проверяет смену пользователя командой `gosu nobody true`. Ранее добавленное исправление zlib сохранено.

При подготовке выпуска два прогона CI отклонили скачанный архив gosu из-за несовпадения SHA-256. Повторно скачанный официальный архив совпал с исходным проверенным файлом. Для следующих сборок указан прямой официальный адрес `codeload.github.com`, без промежуточного перенаправления с `github.com`. Версия, исходники и закреплённая SHA-256 не изменены. Неверный ответ по-прежнему останавливает сборку.

## Проверки и ограничения

- Оба Docker-образа собраны, итоговые бинарники показывают Caddy 2.11.9 и gosu 1.20 на Go 1.27.3
- Новый PostgreSQL инициализировал отдельную пустую БД и создал роли приложения и мигратора с production-ограничениями контейнера
- Мигратор успешно подключился своей ролью. Прикладных SQL-миграций в текущем каркасе ещё нет. Контрольная запись сохранилась после удаления тестового контейнера PostgreSQL и повторного запуска с тем же volume
- Локальный Caddyfile прошёл `caddy validate`
- Временный шлюз с production Caddyfile проверен через HTTP: healthcheck и SHA выпуска, readiness существующего локального API, JSON 404, SPA-маршрут, защитные заголовки и immutable-статика
- Тестовый шлюз выполнял только GET-запросы к локальному API. Рабочие контейнеры и их данные не менялись

Полный запуск изолированного production Compose на Docker Desktop 29.2.1 / Compose 5.0.2 остановился с `EOF` при создании PostgreSQL. Ошибка воспроизводится и на прежнем образе. Эти попытки не считаются успешной интеграционной проверкой. После отправки ветки нужно дождаться существующего Linux job `Delivery integration`, который проверяет миграции, Blue-Green и откат.

В инструментах сборки PWA остаются четыре LOW-записи цепочки Workbox → `deepmerge 4.3.1`. Для [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) исправленного релиза нет. Несовместимый откат `vite-plugin-pwa` и подавление записи не применялись. Полный `npm audit` продолжает сообщать о них, `npm audit --omit=dev` возвращает 0 находок.

Нулевой результат сканирования относится к проверенным образам и базе на дату проверки. При обновлении базовых образов, Go или закреплённых библиотек проверку нужно повторить. Результат Linux CI фиксируется в PR на актуальном коммите. Публикация образов и выкладка на VPS выполняются отдельно.
