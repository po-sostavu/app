# Правила PWA

- Установка зависимостей без согласования запрещена
- Перед изменениями читать корневой `AGENTS.md`, `docs/charter.md` и `docs/architecture.md`
- Клиентские команды выполнять из `apps/pwa/`. Общие команды и OpenSpec — из корня репозитория
- Стек: React, TypeScript, Vite, Mantine, React Router, TanStack Query, `vite-plugin-pwa`. Зависимости — npm. Отдельный пакет в `apps/pwa`
- Линтинг — ESLint в flat-конфигурации `eslint.config.mjs`, с typescript-eslint и правилами React Hooks. Запускать с `--max-warnings=0`
- Форматирование — Prettier с общей корневой конфигурацией. Использовать eslint-config-prettier для отключения конфликтующих правил. Запускать Prettier отдельно от ESLint
- Проверку типов выполнять отдельно через `tsc --noEmit`. Линтинг её не заменяет
- Использовать команды `npm run lint`, `npm run format`, `npm run format:check` и `npm run typecheck`. `npm run check` объединяет проверки. В CI формат только проверяется, без исправления файлов
- Версии инструментов фиксировать в devDependencies и lock-файле, одинаково для локального запуска и CI. Генерируемые файлы, сборки и сторонний код исключать из форматирования и линтинга
- Бизнес-логику тестировать в Vitest, среда Node.js, файлы `*.test.ts` рядом с моделью или сценарием. Команда однократного запуска — `npm test` (`vitest run`)
- Тесты нужны для бизнес-правил, значимых сценариев, их границ и ошибок. Не писать тест на каждый компонент, DTO, геттер или обёртку и не повторять в тестах реализацию
- Не вводить целевой процент покрытия. Для задачи без бизнес-логики новые тесты не обязательны
- React Testing Library, jsdom и Playwright в базовый набор MVP не входят. Компонентные и E2E-тесты не требуются для каждой задачи. Установку новых инструментов согласовывать
- Архитектуру проверять через `npm run lint:fsd` (Steiger и официальный FSD-плагин). Включать в `npm run check`
- Интерфейс проектировать mobile-first как приложение: компактная шапка, рабочая область и нижняя навигация. Учитывать safe area и нажатия пальцем. Не заменять каркас приложения рекламным лендингом
- Следовать FSD: зависимости направлены от `app` к `pages`, `widgets`, `features`, `entities`, `shared`. Допустим импорт с любого нижележащего слоя
- Точка входа — `src/main.tsx`. Слой `app` разделён по назначению: `init` — провайдеры и граница ошибок, `router` — маршруты, `layouts` — оболочка, `styles` — глобальные стили и тема, `pwa` — состояние сети и обновление. Стили оболочки изолировать CSS Modules. Новые пустые сегменты не создавать
- Используй алиасы
- Срезы одного слоя не связывать прямыми импортами. Использовать композицию на верхнем слое или нижележащие сущности и контракты
- Для внешних импортов использовать публичный API среза. Не обращаться к его внутренним файлам
- `shared` не зависит от продуктовых слоёв. Бизнес-логику конкретной возможности не переносить в общие утилиты ради повторного использования
- Слои `widgets` и `entities` добавлять по необходимости. Не создавать пустые структуры заранее
- Серверное состояние вести через TanStack Query. На клиенте оставлять состояние интерфейса, выбор и предпросмотр фото, показ состояния обработки и готового результата
- Профиль пользователя содержит свободный текст предпочтений и бюджет из списка. Читать и сохранять его через API приложения. Локальный черновик и кэш PWA не заменяют серверный профиль в PostgreSQL. После сохранения изменений обновлять отображаемую персональную оценку и альтернативы по данным API
- Предусматривать простое сравнение шампуней по составу, персональной оценке и причинам соответствия. Экологичность и этичность не показывать как оценку загруженного состава. Использовать только для альтернатив с подтверждающими сведениями о товаре или бренде. Ссылки на магазины могут быть обычными
- Показывать бесплатный месячный лимит и остаток демопакета по данным API. Исходный настраиваемый ориентир — 10 сканирований. Демоактивация явно обозначается, не требует платёжных данных и не называется покупкой. Сначала расходуется бесплатный остаток, затем пакет. Клиент сам не устанавливает доверенный остаток
- Ошибка анализа не расходует доступные сканирования. Повтор запроса и открытие готового результата не создают новое списание. Размер демопакета, правила повторной активации, смены месяца и пересчётов определяются до реализации. Расчётные 20 сканирований за 199 ₽ из устава не являются утверждённым тарифом
- В MVP не добавлять реальные платежи, подписку, историю сканирований и диалог с ИИ. Интерес к пакетам и демонстрационные активации учитывать в аналитике отдельно от будущих покупок. Партнёрская интеграция не обязательна для основного сценария
- Фото отправлять в API приложения одним действием для полного анализа. OCR и последующий ИИ-разбор выполняет сервер. Не добавлять промежуточный редактор распознанного текста, подтверждение или отдельный запуск ИИ из PWA
- Локальный OCR и Tesseract.js не использовать, включая резервный путь без сети. До загрузки сообщать пользователю о передаче фото внешнему OCR-сервису. При сбое сохранять выбранное фото и настройки профиля в текущем сценарии. Безопасный повтор выполнять по контракту API
- Базовая политика PWA: кэшировать только статическую оболочку, офлайн-навигация — только `/` и `/profile`, API и персональные данные не кэшировать. Обновление — по кнопке пользователя. Расширение политики определять в соответствующем OpenSpec change
- Общий локальный шлюз использует `infra/Caddyfile`: отдаёт PWA и направляет `/api` и `/api/*` в Go API с удалением префикса `/api`. `apps/pwa/Dockerfile` собирает статику и единственный контейнер шлюза. Второй Caddy и Caddy внутри Go не нужны. Локальный шлюз работает по HTTP на loopback. Внешний HTTPS и CD настраиваются отдельно
- При изменениях API согласовывать PWA и Go-бэкенд через OpenAPI-контракт, создаваемый вместе с первыми API-методами
- Выполнять проверки, применимые к изменению. Не указывать команды приложения как работающие до их настройки и проверки
- Тесты бизнес-логики выполнять в CI вместе с линтингом, форматированием и проверкой типов. Не добавлять фиктивные тесты на этапе создания каркаса
- Изменения постоянных архитектурных правил отражать в `docs/architecture.md` и этом файле. Решения отдельной задачи описывать в её `design.md`

## Рекомендации агенту: ошибки и параллельные запросы

- Обрабатывать сетевую ошибку, тайм-аут и неуспешный ответ API: завершать состояние загрузки и показывать понятную ошибку с возможностью безопасного повторного действия
- При сбое сохранять выбранное фото и введённые пользователем данные профиля в текущем сценарии. Не сбрасывать всю страницу и независимые части интерфейса
- Учитывать параллельные запросы и устаревшие ответы: результат старого профиля или состава не должен подменять результат актуального. Использовать соответствующие данным ключи запросов, отмену и проверку актуальности результата
- Не повторять автоматически команды изменения состояния и платные операции без гарантии идемпотентности API. Блокировка кнопки защищает интерфейс от повторного нажатия, но не заменяет защиту от дублей на сервере
- Для команды, требующей `Idempotency-Key`, создавать ключ один раз на логическую операцию и передавать его во всех повторах, включая повтор после сетевой ошибки. Не генерировать новый ключ внутри каждой попытки HTTP-запроса
- Новое намеренное действие или изменение значимых входных данных получает новый ключ. Не подменять ключ после тайм-аута для принудительного повторного выполнения. При неизвестном исходе сохранять ключ и выяснять состояние прежней операции по контракту API
- При недоступности самого бэкенда показывать ошибку связи. Не ожидать JSON-ответа от неработающего процесса. Готовиться к ответу шлюза, сетевой ошибке и отсутствию тела ответа

## Рекомендации агенту: безопасность клиента

- Считать код и конфигурацию PWA публичными. `VITE_*`, значения, подставленные в сборку, минификация и обфускация не обеспечивают секретность
- Не помещать ключи OCR- и ИИ-провайдеров, пароли БД, приватные ключи и ключи подписи в JS/HTML, браузерное окружение, localStorage, sessionStorage, IndexedDB, service worker или Cache Storage. Внешние OCR- и ИИ-вызовы выполняет только бэкенд
- Production CSP формируется при сборке: скрипты только с текущего origin, соединения — с текущим origin и origin проверенного API. Inline-стили разрешены для Mantine. Inline-скрипты и eval не разрешать. Запрет встраивания задаётся HTTP-заголовками Caddy. При изменении API-адреса или способов загрузки ресурсов проверять политику в браузере
- Не хранить сессионные идентификаторы, access/refresh-токены и пароли в доступных JavaScript браузерных хранилищах. При cookie-аутентификации использовать серверные HttpOnly/Secure cookies с подходящей SameSite-политикой и серверной защитой от CSRF. Ключ идемпотентности не является токеном авторизации
- Не кэшировать в service worker секреты, ответы авторизации и приватные ответы API без явной безопасной политики. При завершении пользовательской сессии очищать привязанные к ней данные и кэш TanStack Query, чтобы другой пользователь их не получил
- Рассматривать клиентскую валидацию и скрытие кнопок как удобство интерфейса: права доступа и ограничения операции проверяются сервером
- Ответы ИИ и введённый текст считать недоверенными. Отображать их как текст. Не передавать без обработки в `dangerouslySetInnerHTML`, `eval` или исполняемые URL. Для действительно необходимого HTML применять согласованную санитизацию
- Не отправлять фото, токены, полный состав и профиль в консоль, аналитику или отчёты об ошибках. Фото передавать в API приложения для полного анализа. Дальнейшую передачу распознанного текста в ИИ выполняет бэкенд
