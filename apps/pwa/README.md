# PWA ПоСоставу

> Мобильное приложение для разбора состава и выбора шампуня.

Технический каркас на React, TypeScript и Mantine. Есть экраны «Анализ» и «Профиль», нижняя навигация и статический офлайн-кэш. Отправка фото, анализ, сохранение профиля и другие продуктовые функции будут реализованы отдельно вместе с API.

## Возможности

- Mobile-first оболочка Mantine AppShell с учётом safe area
- Заготовки экранов анализа и профиля, нижняя навигация и экран 404
- Тема Mantine с локальным шрифтом Manrope Variable
- Manifest и установочные иконки из предоставленного логотипа
- Кнопка установки в шапке: системное окно или инструкция для устройства
- Статическая оболочка доступна без сети после первого посещения
- Обновление приложения по кнопке пользователя
- Валидация публичной конфигурации при запуске и сборке
- Проверка FSD через Steiger
- Сборка Docker-образа с непривилегированным пользователем

## Стек

- Frontend: React, TypeScript, Vite
- Server state: TanStack Query
- Routing: React Router
- UI: Mantine, CSS Modules, Tabler Icons
- PWA: vite-plugin-pwa, Workbox
- Architecture: Feature-Sliced Design
- Code quality: ESLint, Prettier, Steiger
- Tests: Vitest
- Package manager: npm

## Переменные окружения

| Переменная          | По умолчанию | Назначение                                   |
| ------------------- | ------------ | -------------------------------------------- |
| `VITE_API_BASE_URL` | `/api`       | Публичный базовый адрес будущего API-клиента |

Разрешён путь от корня или HTTPS URL без логина, пароля, query и fragment. HTTP разрешён только в development для `localhost`, `127.0.0.1` и `[::1]`. Недопустимое значение останавливает запуск или сборку.

Для абсолютного production URL требуется доменное имя: IP-адреса отклоняются из-за ограничений CSP. Путь `/api` подходит и для локального просмотра сборки.

Конфигурация подставляется **во время сборки** и видна пользователю браузера. Ключи OCR, ИИ и другие секреты хранятся только на сервере. Автоматическая публикация всех `VITE_*` отключена: в клиент передаётся только проверенный `VITE_API_BASE_URL`.

Продуктовый API-клиент пока не реализован. В общем Docker-окружении путь `/api` обслуживает шлюз из `infra/Caddyfile`. Сама переменная не создаёт прокси. Режимы `npm run dev` и `npm run preview` запускают PWA отдельно.

## Локальный запуск

### Требования

- Node.js 24.19.0
- npm 11.x. Проверяемая версия — 11.6.2

Все команды приложения выполняются из `apps/pwa`.

### Установка

```sh
npm ci
```

### Настройка окружения

Без `.env` используется адрес `/api`. Для изменения адреса скопируйте пример в PowerShell:

```powershell
Copy-Item .env.example .env
```

```dotenv
VITE_API_BASE_URL=/api
```

### Запуск

```sh
npm run dev
```

Приложение доступно на `http://127.0.0.1:5173`. Бэкенд для запуска оболочки не требуется. Это отдельный режим с hot reload. Общий контейнерный запуск ниже использует готовую сборку.

## PWA

Service worker отключён в режиме разработки. Для проверки установки, офлайн-режима и обновлений соберите приложение:

```sh
npm run build
npm run preview
```

Откройте `http://127.0.0.1:4173`. Полноценная работа PWA требует localhost или HTTPS.

Кнопка «Установить» находится в шапке. Если браузер разрешает программную установку, нажатие открывает его системное окно. Иначе появляется инструкция: на iPhone и iPad — через «Поделиться» и «На экран Домой», в Safari на Mac — добавление в Dock, на Android и остальных компьютерах — доступное действие установки браузера. Если нужного пункта нет, инструкция предлагает совместимый браузер. Само приложение не запускает установку автоматически.

Во время системного запроса повторное нажатие заблокировано. Отмена не мешает пользоваться приложением. При ошибке доступна ручная инструкция. Кнопка скрывается в установленном окне PWA, после события `appinstalled` и при положительной проверке собственной PWA через `getInstalledRelatedApps`.

В manifest указана ссылка на собственный `/manifest.webmanifest` без абсолютного `id` связанного приложения. Она позволяет проверять установку на поддерживаемом Android. В обычных вкладках других браузеров установленность может оставаться неизвестной, поэтому кнопка иногда видна и после установки. Пустой ответ или ошибка проверки не означают, что приложение установлено. Постоянный флаг в `localStorage` не сохраняется, чтобы удаление PWA не оставляло кнопку скрытой.

Кэшируются HTML, JS, CSS, локальный шрифт и иконки. Без сети доступны оболочки `/` и `/profile`. API-ответы, фото и персональные данные не кэшируются. Очереди фоновой отправки нет. Анализ фото требует сети, локальный OCR не используется.

Новая версия предлагает действия «Обновить» и «Позже». Приложение не перезагружается без выбора пользователя. Проверку PWA следует выполнять на целевых мобильных устройствах: наличие manifest не гарантирует одинаковую поддержку установки в браузерах.

## Сборка и запуск через Docker

`apps/pwa/Dockerfile` собирает статику PWA и единственный контейнер шлюза Caddy. Конфигурация находится в `infra/Caddyfile`: шлюз отдаёт PWA, обрабатывает SPA-маршруты и направляет `/api` и `/api/*` в отдельный Go API. В Compose этот сервис называется `gateway`.

Caddy собирается из отдельного Go-модуля `infra/caddy` с закреплёнными исправлениями зависимостей. Компилятор в итоговый образ не попадает. Версии и проверки — в [отчёте безопасности контейнеров](../../docs/container-security.md).

Общий запуск выполняется **из корня репозитория** после подготовки `infra/.env` по [инструкции инфраструктуры](../../infra/README.md#запуск):

```sh
task up
task check
```

Приложение доступно на `http://127.0.0.1:8080`, готовность API — на `/api/readyz`. Порт меняется через `WEB_PORT` в `infra/.env`. Проверка жизни самого шлюза — `/healthz`. Команда запуска сначала поднимает БД и выполняет миграции отдельным контейнером, затем запускает API и шлюз. Пользовательские сценарии API и их подключение к интерфейсу реализуются отдельно.

Для отдельной сборки образа:

```sh
docker build -f apps/pwa/Dockerfile -t posostavu-pwa:local .
```

Для другого адреса API передайте параметр сборки:

```sh
docker build -f apps/pwa/Dockerfile --build-arg VITE_API_BASE_URL=https://api.example.test/api -t posostavu-pwa:local .
```

`docker run -e VITE_API_BASE_URL=...` не изменяет готовую сборку. Локальные `.env`, зависимости и результаты сборки исключены из build context.

Контейнер работает от непривилегированного пользователя. Compose ограничивает права и делает его файловую систему доступной только для чтения. Неизвестные клиентские адреса открывают экран 404, отсутствующие статические файлы возвращают HTTP 404. Неизвестные API-маршруты, включая `/api` и `/api/missing.js`, возвращают JSON 404 от Go, без подмены HTML приложения. При недоступности API шлюз возвращает короткую ошибку 503 с `Cache-Control: no-store`. PWA и `/healthz` продолжают работать.

Production CSP разрешает скрипты только с текущего origin, соединения — с текущим origin и доменом настроенного API. Inline-стили разрешены для Mantine. Inline-скрипты и `eval` запрещены. Caddy запрещает встраивание приложения в iframe. Политика ресурсов входит в HTML и сохраняется в офлайн-кэше.

Локальный шлюз раздаёт HTTP только на loopback. Внешний HTTPS и порядок выкладки описаны в [регламенте CD](../../docs/cd.md). Остановка общего окружения — `task down`, данные PostgreSQL сохраняются. В контейнерном запуске нет hot reload: изменения интерфейса применяются после повторного `task up` со сборкой образа.

## Команды

| Команда                  | Описание                                    |
| ------------------------ | ------------------------------------------- |
| `npm run dev`            | Запуск в режиме разработки                  |
| `npm run build`          | Проверка типов и сборка в `dist`            |
| `npm run preview`        | Локальный просмотр сборки                   |
| `npm run lint`           | ESLint без предупреждений                   |
| `npm run lint:fsd`       | Проверка FSD через Steiger                  |
| `npm run typecheck`      | Проверка TypeScript без сборки              |
| `npm run format`         | Prettier и сортировка импортов              |
| `npm run format:check`   | Проверка формата без изменения файлов       |
| `npm test`               | Однократный запуск Vitest                   |
| `npm run test:watch`     | Vitest в режиме наблюдения                  |
| `npm run check`          | Формат, ESLint, FSD, типы и тесты           |
| `npm run audit`          | Проверка известных уязвимостей зависимостей |
| `npm run generate:icons` | Генерация иконок из `public/logo.png`       |

ESLint и Prettier запускаются раздельно. Общая конфигурация Prettier находится в корне репозитория. Импорты группируются по внешним пакетам и слоям FSD. Порядок импортов с побочными эффектами, включая CSS, сохраняется.

Тесты каркаса проверяют публичную конфигурацию и отсутствие секретных значений в ошибках валидации. Тесты продуктовых сценариев появятся вместе с их реализацией. В [CI](../../docs/ci.md) выполняются `npm ci`, `npm run check`, `npm run build` и аудит зависимостей. CD настраивается отдельно.

Для исправления транзитивных зависимостей временно заданы адресные `overrides` для `minimatch` и `glob`. Полный `npm run audit` пока возвращает ненулевой код из-за `deepmerge` в инструментах сборки. У опубликованной версии нет исправления. Текущее состояние зависимостей и образов — в [отчёте безопасности контейнеров](../../docs/container-security.md).
