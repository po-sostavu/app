# Проверка каркаса

07.11.2026. Проверки выполнены для `feature/prd-33-pwa-scaffold` перед слиянием в `develop`. CI/CD не настроен. После аудита и рефакторинга выполнены следующие проверки.

## Локальные проверки

- `npm run check`: Prettier, ESLint, Steiger без исключений, TypeScript и 28 тестов валидации окружения проходят
- Steiger ранее проверен временным запрещённым импортом из `shared` в `pages`: получены `fsd/forbidden-imports` и ненулевой код завершения. Проверочный файл удалён
- `npm run build`: созданы статическая сборка и service worker с 17 статическими записями. Шрифты поставляются отдельными файлами. Inline-font из CSS исключён для совместимости с CSP
- `npm ls minimatch glob deepmerge`: дерево зависимостей согласовано. Обычный `npm ci` воспроизведён в Linux при контейнерной сборке
- Валидация отклоняет credentials, небезопасные схемы, недопустимый hostname и production IP literal. Ошибка не повторяет значение настройки. Отдельная сборка с HTTPS API проверена: в CSP включён его origin без пути
- Исходный логотип сохранён побайтово, корневой README сохраняет UTF-16 LE BOM. Документация согласована с фактическими сегментами `app` и временным назначением Caddy

## Браузер и PWA

Изолированный Chrome: 320×568, 390×844, 768×1024, 1366×900 и 844×390. Проверены переходы «Анализ» / «Профиль», активный пункт, зоны нижней навигации от 48 px, отсутствие горизонтального переполнения и перекрытия последнего действия нижней панелью. Рабочая область ограничена по ширине. Снимки мобильной оболочки просмотрены. 404 возвращает на главную. Ошибок JavaScript при обычной работе нет.

Safe area эмулирована отдельно: 44 px сверху и 34 px снизу. Шапка, содержимое и навигация находятся в доступной области. Кнопкам темы и ссылке бренда задана минимальная высота 48 px.

Проверены manifest, иконки, активный service worker и статический кэш. При заблокированной сети открываются и перезагружаются оболочки `/` и `/profile`. Запрос API не проходит, персональные данные не появляются в кэше. Состояние `navigator.onLine` эмулировалось отдельно, поскольку Chrome сбрасывал его при переходе между документами.

При новой версии worker появляется предложение обновления. «Позже» сохраняет страницу, «Обновить» активирует worker и перезагружает приложение. Исправлена очистка старой ошибки при повторной попытке. На время вызова обновления кнопки блокируются.

Production CSP проверена в браузере: штатные шрифты, интерфейс и worker работают без нарушений политики. Внедрённый inline-скрипт не исполняется, соединение с посторонним origin блокируется. Встраивание страницы в iframe запрещено заголовками Caddy.

## Контейнер

Итоговый образ собран через многоэтапный Dockerfile. Caddy обновлён до 2.11.9, `zlib` — до 1.4-r0. Контейнер работает с UID 10001. Healthcheck успешен. Главная, профиль, manifest, worker и ресурсы возвращают 200. Отсутствующий JS — 404. `/api` и `/api/profile` — 503 с `no-store`. Проверены заголовки защиты от встраивания и работа CSP после обновления zlib.

Caddy здесь обслуживает временный самостоятельный каркас. Общий шлюз PWA / Go API, HTTPS, Compose и CD остаются отдельной задачей.

## Аудит безопасности

`npm audit --omit=dev`: 0 находок. Полный аудит: 4 low вместо исходных 16 записей. Все относятся к `deepmerge` в сборочной цепочке Workbox. Находки не скрыты настройками аудита. Результаты проверки Caddy и остающиеся риски описаны в [отчёте безопасности](security-audit.md).

Trivy проверил итоговый локальный образ с `--network none`, через tar, смонтированный только для чтения. База уязвимостей была скачана отдельно без доступа к образу проекта. Итог: 0 записей в пакетах Alpine и 6 записей в Go-зависимостях Caddy (2 HIGH, 3 MEDIUM, 1 UNKNOWN). `zlib` больше не отмечается. Это подтверждает устранение OS-находки, но не закрывает оставшиеся записи бинарника.

Браузерные проверки выполнены временным инструментом вне зависимостей приложения. Проверки не подтверждают готовность продуктовых сценариев, серверного API или установку PWA на всех мобильных платформах.
