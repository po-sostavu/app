## ADDED Requirements

### Requirement: Воспроизводимый каркас

Приложение SHALL устанавливаться через npm из lock-файла, запускаться локально и собираться без работающего API.

#### Scenario: Локальная сборка

- **WHEN** разработчик выполняет `npm ci`, `npm run check` и `npm run build` в `apps/pwa`
- **THEN** проверки проходят и создаётся статическая сборка `dist`

### Requirement: Оболочка и оформление

Оболочка SHALL использовать Mantine AppShell, заданные цвета, Manrope и предоставленный логотип, проектироваться mobile-first и иметь маршрут 404 с возвратом на главную. Основные экраны SHALL быть доступны через нижнюю навигацию с зонами нажатия не менее 48 px и учётом безопасной области экрана. Экраны анализа и профиля остаются заготовками без отправки и сохранения данных.

#### Scenario: Навигация на телефоне

- **WHEN** пользователь открывает приложение на экране шириной 320 px и выбирает «Профиль» в нижней навигации
- **THEN** отображается заготовка профиля, активный раздел обозначается текстом и состоянием ссылки, горизонтальной прокрутки нет, содержимое не перекрывается навигацией

#### Scenario: Неизвестный адрес

- **WHEN** пользователь открывает неизвестный путь при доступной сети
- **THEN** видит страницу 404 и рабочую ссылку на главную

### Requirement: Статическое PWA

Приложение SHALL поставлять manifest и установочные иконки, кэшировать только статическую оболочку и запрашивать применение обновления. API, фотографии и персональные данные SHALL NOT кэшироваться service worker.

#### Scenario: Повторное открытие без сети

- **WHEN** установленный service worker уже сохранил оболочку и пользователь открывает `/` или `/profile` без сети
- **THEN** соответствующая оболочка загружается и показывает сообщение о необходимости сети для анализа, персональные данные из кэша не выдаются

#### Scenario: Новая версия

- **WHEN** обнаружен обновлённый service worker
- **THEN** пользователь может применить обновление или отложить его без принудительной перезагрузки

### Requirement: Проверка окружения

Каркас SHALL проверять `VITE_API_BASE_URL` до запуска dev/build, использовать `/api` при отсутствии значения и передавать в клиент только разрешённую публичную настройку.

#### Scenario: Ошибочный URL

- **WHEN** значение пустое, содержит credentials, query, fragment, небезопасную схему, недопустимый hostname, IP-адрес в production URL или HTTP вне локальной разработки
- **THEN** запуск завершается ошибкой с именем переменной без вывода её значения

### Requirement: Контейнерная сборка

Dockerfile SHALL собирать приложение через npm lock-файл и отдавать статические файлы через Caddy на порту 8080 от непривилегированного пользователя.

#### Scenario: Запуск контейнера

- **WHEN** образ собран из корня репозитория и контейнер запущен
- **THEN** главная, ресурсы, manifest и клиентская 404 доступны, а `/api` возвращает 503 вместо HTML приложения

### Requirement: Защитная политика браузера

Production-сборка SHALL ограничивать источники ресурсов через CSP, разрешать соединения только с текущим origin и origin проверенного API-адреса. Раздача через Caddy SHALL запрещать встраивание приложения в iframe. Политика SHALL сохранять работу Mantine, навигации и service worker.

#### Scenario: Ограничение исполняемого кода

- **WHEN** браузер открывает production-сборку и происходит попытка исполнить внедрённый inline-скрипт
- **THEN** CSP блокирует скрипт, штатное приложение и service worker продолжают работать
