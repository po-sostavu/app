## Context

В репозитории есть архитектурные правила, но нет приложения. Пользователь отдельно поручил реализовать каркас PWA и заменил прежний выбор менеджера пакетов на npm. Технический объём согласован этим поручением.

## Goals / Non-Goals

Цель: воспроизводимый старт разработки PWA, локальные проверки и контейнер для статической сборки.

Продуктовые сценарии и API остаются отдельными изменениями. Экраны «Анализ» и «Профиль» остаются заготовками без загрузки и сохранения пользовательских данных. Тема не меняет название продукта «ПоСоставу».

## Decisions

- Один npm-пакет и `package-lock.json` в `apps/pwa`. Для единственного JS-приложения npm workspaces не нужны. Node 24, точные версии прямых зависимостей. TypeScript выбирается в диапазоне, который поддерживает typescript-eslint
- FSD начинается со слоёв `app`, `pages`, `shared`. Алиас `@/` и публичные API срезов. MantineProvider и QueryClientProvider подключаются один раз. Общий разбор и профиль пока отсутствуют
- После аудита `src/main.tsx` отвечает только за запуск React, `app/App.tsx` объединяет провайдеры и роутер. Сегменты `init`, `router`, `layouts`, `styles`, `pwa` разделяют ответственность по назначению и проходят рекомендуемые правила Steiger без исключений. CSS оболочки изолирован модулем. Тема находится в `app/styles`. QueryClient создаётся на экземпляр провайдера
- Mobile-first AppShell: компактная шапка, рабочая область, нижняя навигация «Анализ» / «Профиль» с зонами нажатия от 48 px. Safe area учитывается сверху и снизу. `100dvh` следует за высотой окна. На широком экране контент ограничен 640 px. Рекламного hero, промосекций и футера со слоганом нет
- Одна светлая тема: Manrope, цвета и шкала отступов из задания, рамки без декоративных теней. Шрифт поставляется вместе с приложением. Исходный PNG сохраняется. Установочные иконки генерируются из него воспроизводимой командой
- Статическая оболочка и её локальные ресурсы предварительно кэшируются service worker. Runtime-кэширование, очередь фоновых отправок и кэш API не включаются. SPA fallback разрешён только для известных маршрутов `/` и `/profile`. `/api` и произвольные пути не получают кэшированный HTML. Обновление ожидает явного нажатия пользователя. В dev service worker отключён
- Единственная настройка клиента — `VITE_API_BASE_URL`, по умолчанию `/api`. Допустим путь от корня или HTTP(S) URL без credentials, query и fragment. HTTP допустим только локально в development. Проверка выполняется перед dev/build. В браузер передаётся только это проверенное значение. Секреты не входят в конфигурацию PWA
- Prettier с плагином сортировки импортов, порядок групп соответствует FSD. Импорты с побочными эффектами сохраняют порядок. ESLint проверяет JS/TS и Hooks. Steiger с рекомендуемым FSD-плагином проверяет структуру и зависимости слоёв. TypeScript запускается отдельно. Vitest работает в Node и проверяет границу конфигурации. Фиктивных тестов UI нет
- Docker собирает приложение через `npm ci` и отдаёт `dist` через Caddy на 8080 от непривилегированного пользователя. Публичная переменная задаётся во время сборки. Переменные runtime env не меняют готовый JS. `/api` возвращает 503 до подключения отдельного шлюза/API. HTML, manifest и service worker перепроверяются. Хешированные assets имеют длительный кэш. TLS/Compose/CD — отдельная задача
- Production CSP добавляется в HTML при сборке и действует в сохранённой офлайн-оболочке. Origin API берётся только из проверенного URL. Скрипты разрешены только с текущего origin, без inline/eval. Inline-стили разрешены для Mantine. `frame-ancestors` задаётся отдельным HTTP-заголовком Caddy, поскольку meta эту директиву не поддерживает. Дополнительно задан X-Frame-Options
- Шрифты выводятся отдельными файлами (`assetsInlineLimit: 0`) для строгого `font-src 'self'`. Абсолютный URL API в production требует доменное имя: IP literal не используется в CSP. Текущий Caddyfile временно обслуживает самостоятельный каркас. При общей настройке CD его правила переходят в шлюз `infra/Caddyfile`, общий для PWA и отдельного Go-сервиса
- Уязвимые версии minimatch и glob заменены адресными npm overrides. Версия minimatch 5 у filelist не затронута. Это временное решение до обновления зависимостей инструментами. Оставшаяся находка deepmerge относится к сборочной цепочке Workbox. Подробности и результаты аудита — в `verification.md`

## Risks / Trade-offs

- Кэш оболочки не делает анализ доступным без сети. Интерфейс сообщает об отсутствии соединения
- После изменения публичной конфигурации контейнер надо пересобрать
- В каркасе нет API-запросов: правильность будущего API-контракта этой работой не подтверждается

## Migration Plan

Установить зависимости командой `npm ci` из `apps/pwa`, запустить проверки и сборку. Существующих пользовательских данных и миграций нет. Изменение проходит через feature-ветку и PR в `develop`.

## Open Questions

Вопросов, блокирующих каркас, нет. API-контракт, идентификация пользователя и продуктовые экраны определяются отдельно.
