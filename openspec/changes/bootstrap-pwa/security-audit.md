# Аудит безопасности каркаса PWA

Дата: 07.11.2026. Проверены зависимости npm, публичная конфигурация, политика PWA, Dockerfile и публичный базовый образ Caddy. Это аудит технического каркаса, а не проверка ещё не реализованных API, авторизации и обработки фото.

## Зависимости npm

| Проверка               | До исправлений                 | После исправлений |
| ---------------------- | ------------------------------ | ----------------- |
| `npm audit`            | 16 записей: 14 moderate, 2 low | 4 записи low      |
| `npm audit --omit=dev` | 0                              | 0                 |

Транзитивные `minimatch` и `glob` обновлены через адресные `overrides` до 11.0.5 и 14.0.4. Исправления подтверждены в [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) и [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4). Старый `minimatch@5` с другим API не подменяется. Overrides временные: их нужно пересматривать при обновлении основных инструментов. `npm audit fix --force` не применялся.

Четыре оставшиеся записи относятся к одной уязвимости [deepmerge, GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4), распространённой по цепочке `vite-plugin-pwa → workbox-build → @rollup/plugin-node-resolve → deepmerge`. Исправленного релиза `deepmerge` на дату аудита нет. В установленном `@rollup/plugin-node-resolve@16.0.3` найден единственный вызов `deepMerge({}, defaults)` с константами. Пользовательские данные приложения в этот вызов не поступают; зависимость используется при сборке и не копируется в runtime-контейнер. Находка остаётся открытой до исправления upstream; она не исключена из аудита.

## Конфигурация клиента

В коде каркаса не обнаружены небезопасные HTML-вставки, `eval`, хранение токенов или персональных данных в браузерных хранилищах. В сборку передаётся только разрешённая публичная переменная API. Проверка окружения отклоняет credentials и небезопасные значения без их вывода в ошибку.

Production HTML содержит CSP: скрипты только своего origin, без inline JavaScript и `unsafe-eval`; соединения ограничены своим origin и настроенным API. Inline-стили разрешены для Mantine. Caddy дополнительно запрещает встраивание через `frame-ancestors 'none'` и `X-Frame-Options: DENY`. Service worker кэширует статическую оболочку; ответы API и персональные данные в runtime-кэш не добавляются.

Все шесть записей Go из таблицы остаются открытыми, находка `zlib` отсутствует. Обновление APK не меняет встроенные зависимости бинарника Caddy.

Это оценка конфигурации, а не доказательство недостижимости уязвимых функций. Находки не скрыты и требуют пересмотра перед развёртыванием и изменением конфигурации сервера.

Caddy в каркасе временно обеспечивает локальную проверку контейнерной раздачи PWA. Общий шлюз и его конфигурация будут оформлены отдельно в инфраструктуре; текущий контейнер не определяет окончательную схему развёртывания.

## Метод и ограничения проверки образа

Автоматическая проверка разрешений отклонила сканирование локального образа через Docker Scout из-за возможной передачи метаданных проекта во внешний сервис. Этот запрос не повторялся. Проверка публичного образа через Scout требовала входа в Docker; вход и действия с учётными данными не выполнялись.

Вместо этого официальный Trivy запускался локально без mounts, файлов проекта и Docker socket, с отключённой телеметрией и проверкой новых версий. Он получал из сети только публичный образ и базу уязвимостей. Временный контейнер удалён через `--rm`.

```sh
docker run --rm --cap-drop ALL --security-opt no-new-privileges --memory 2g --cpus 2 aquasec/trivy:0.76.2 image --disable-telemetry --skip-version-check --scanners vuln --image-src remote --timeout 4m --no-progress --format json docker.io/library/caddy:2.11.9-alpine@sha256:0bbb055bda6793c999bde78b1b5ce3e89f829fb031af2cf50056ea1246559fee
```

Для проверки итогового образа сначала выполнен локальный `docker image save` в отдельный временный tar. Публичная база CVE загружена в отдельный новый Docker volume контейнером без доступа к этому архиву и проекту. Затем сканер получил только read-only tar и volume с базой. Его параметры: `--network none`, `--offline-scan`, `--skip-db-update`, `--skip-java-db-update`, `--disable-telemetry`, `--skip-version-check`, `--scanners vuln`, `--input /scan/image.tar`, ограничение времени 4 минуты. Отключённая сеть и read-only mount подтверждены через `docker inspect`; содержимое локального образа не передавалось внешним сервисам. Временный архив и выделенный volume удалены после проверки.

Аудит версий не доказывает отсутствие неизвестных уязвимостей или возможность эксплуатации каждой найденной записи. Проверки приложения и сборки фиксируются отдельно в [verification.md](verification.md).
