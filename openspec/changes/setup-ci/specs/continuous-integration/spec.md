# Spec Delta

## Purpose

Автоматически проверять изменения PWA, Go API и контейнерной упаковки до их дальнейшего использования, сохраняя видимый результат каждой проверки без доступа к рабочим секретам.

## ADDED Requirements

### Requirement: Проверка изменений в основных ветках

CI SHALL запускать проверки для открытого или обновлённого PR в `develop` и `main`, а также после push в эти ветки. Ручной запуск SHALL быть доступен после регистрации workflow в основной ветке GitHub.

#### Scenario: Изменение Pull Request

- **WHEN** автор открывает PR в `develop` или отправляет новый коммит в существующий PR
- **THEN** CI проверяет актуальное состояние PR и показывает результаты в GitHub

#### Scenario: Только документация

- **WHEN** PR в `main` изменяет только документацию
- **THEN** workflow запускается и возвращает итоговый статус без пропуска из-за фильтра путей

### Requirement: Проверки приложений и контейнеров

CI SHALL проверять формат, линтинг, FSD, типы, существующие тесты и production-сборку PWA; формат, линтинг, существующие тесты с race detector и сборку Go API; сборку контейнеров PWA, API и миграций. Команды и закреплённые версии SHALL соответствовать локальной разработке.

#### Scenario: Ошибка проверки

- **WHEN** линтер, тест, проверка типов или сборка завершается ошибкой
- **THEN** соответствующее задание и общий статус CI завершаются неуспешно

#### Scenario: Ошибка контейнера миграций

- **WHEN** сборки приложений успешны, но контейнер миграций не собирается
- **THEN** CI не объявляет изменение успешно проверенным

### Requirement: Аудит зависимостей

CI SHALL блокировать успех при известных уязвимостях runtime npm-зависимостей любой серьёзности, npm-зависимостей полного дерева от moderate и выше, а также при уязвимостях, обнаруженных проверкой Go-кода. Низкая серьёзность в dev-зависимостях SHALL оставаться видимой в отчёте. Ошибки обращения к аудит-сервису SHALL не скрываться как успех.

#### Scenario: Найдена уязвимость runtime

- **WHEN** npm-аудит runtime-зависимостей сообщает уязвимость low
- **THEN** аудит и общий статус CI неуспешны

#### Scenario: Только низкая серьёзность в инструментах

- **WHEN** полный npm-аудит обнаруживает только low в dev-зависимостях, а остальные проверки успешны
- **THEN** находки видны в журнале, и CI может завершиться успешно

### Requirement: Изоляция и достоверность результата

CI SHALL работать с минимальными правами чтения, без рабочих секретов, публикации образов и деплоя. Проверки SHALL иметь конечное время выполнения. Итоговый успех SHALL требовать успешного завершения всех заданий проверки, включая аудит и контейнеры; отменённая или пропущенная проверка не считается успешной.

#### Scenario: Недоверенный Pull Request

- **WHEN** проверяется PR из внешней ветки или форка
- **THEN** проверяемый код не получает credentials checkout, секреты окружений или права записи в репозиторий

#### Scenario: Новая версия PR

- **WHEN** поступает новый коммит во время предыдущего прогона того же PR
- **THEN** устаревший прогон отменяется, и актуальный коммит получает отдельный результат
