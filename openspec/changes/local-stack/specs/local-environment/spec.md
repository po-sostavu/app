# Spec Delta

## Purpose

Дать разработчику единый локальный адрес приложения, воспроизводимый запуск зависимостей и безопасную остановку с сохранением базы данных перед подготовкой CD.

## ADDED Requirements

### Requirement: Общий локальный запуск

Окружение SHALL запускаться командой `task up` при подготовленной локальной конфигурации. Общие команды SHALL называться `up`, `check`, `down`, `logs` и `ps` без префикса компонента. Команда SHALL дождаться PostgreSQL, выполнить миграции отдельным процессом, запустить API и шлюз и проверить доступность API через общий адрес. Опубликованные порты SHALL быть ограничены loopback.

#### Scenario: Первый запуск

- **WHEN** разработчик запускает окружение с новой БД и корректными локальными паролями
- **THEN** открываются PWA и проверка готовности API на одном origin, рабочая и миграционная роли БД остаются раздельными

#### Scenario: Ошибка миграции

- **WHEN** шаг миграции завершается ошибкой
- **THEN** общая команда завершается неуспешно и не переходит к шагу запуска приложений

#### Scenario: Незаданные пароли

- **WHEN** разработчик копирует `.env.example` без заполнения обязательных паролей
- **THEN** `task up` завершается ошибкой конфигурации до создания БД, значения секретов не выводятся

### Requirement: Разделение маршрутов PWA и API

Шлюз SHALL отдавать статическую оболочку PWA и направлять `/api` и `/api/*` в Go API с удалением ровно префикса `/api`. Ошибки и неизвестные маршруты API SHALL не подменяться HTML приложения. Пути вне указанного префикса SHALL не направляться в API.

#### Scenario: Служебные методы через общий адрес

- **WHEN** клиент запрашивает `/api/readyz` при готовой БД
- **THEN** он получает JSON-ответ Go API со статусом 200 и серверным request ID

#### Scenario: Неизвестный маршрут API

- **WHEN** клиент запрашивает `/api`, `/api/missing` или `/api/missing.js`
- **THEN** он получает ответ 404 от API, а не HTML или статический файл PWA

### Requirement: Доступность интерфейса при отказе API

При отказе API шлюз SHALL продолжать отдавать PWA и собственную проверку жизни. Обращения к API SHALL завершаться ограниченной по времени ошибкой без внутренних сведений. Ответы API, ошибки шлюза, HTML и service worker SHALL не получать бессрочное кэширование. Политика PWA SHALL не кэшировать ответы API.

#### Scenario: API остановлен

- **WHEN** API недоступен после запуска окружения
- **THEN** `/` и `/healthz` доступны, `/api/readyz` возвращает неуспешный HTTP-статус с `Cache-Control: no-store`, без HTML приложения

#### Scenario: БД недоступна

- **WHEN** PostgreSQL перестаёт отвечать
- **THEN** API readiness через шлюз возвращает 503, а PWA и API liveness продолжают работать

### Requirement: Сохранение данных и диагностика

Обычная остановка SHALL сохранять именованный volume PostgreSQL. Документация SHALL описывать запуск, проверку, логи, остановку, конфигурацию портов и локальные секреты. Секреты SHALL не попадать в Git, образ или PWA.

#### Scenario: Повторный запуск

- **WHEN** разработчик останавливает окружение обычной командой и запускает его снова
- **THEN** сохранённые данные БД доступны, и роли не пересоздаются
