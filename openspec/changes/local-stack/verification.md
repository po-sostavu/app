# Проверка общего локального запуска

Дата: 07.11.2026. Задача: [PRD-31](https://linear.app/po-sostavu/issue/PRD-31), подготовка локальной инфраструктуры перед CD.

Первые разделы фиксируют первоначальную проверку до переименования команд. Текущие команды и дополнительный аудит описаны в [дополнении](#переименование-команд-и-аудит).

## Проверенные сценарии

Проверки отказов выполнялись в отдельном Compose-проекте `posostavu-local-stack-check` с новой БД, временными случайными паролями и отдельными loopback-портами. Пользовательские данные не использовались.

| Проверка                                                  | Результат                                                                                                                                        |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `task infra:up` с новой БД                                | PASS: PostgreSQL → отдельные миграции → API и gateway → проверки жизни и readiness                                                               |
| `caddy validate` в read-only контейнере                   | PASS; конфигурация из `infra/Caddyfile`                                                                                                          |
| Docker-сборки PWA/gateway, API и migrate                  | PASS                                                                                                                                             |
| `/`, `/profile`, `/apix`                                  | HTML PWA, HTTP 200, `no-cache`; `/apix` не попадает в API                                                                                        |
| `/api/livez`, `/api/readyz`                               | JSON 200, request ID и `Cache-Control: no-store`                                                                                                 |
| `/api`, `/api?probe=1`, `/api/missing`, `/api/missing.js` | JSON 404 с `not_found`; HTML не возвращается                                                                                                     |
| Статика и заголовки                                       | Хешированный JS — `immutable`; HTML, `sw.js`, manifest — `no-cache`; `nosniff` сохранён                                                          |
| Остановка API                                             | `/api/readyz` — короткий 503 без внутренних сведений и с `no-store`; PWA и `/healthz` — 200; `task infra:check` возвращает ошибку                |
| Приостановка PostgreSQL                                   | Readiness — JSON 503 с `dependency_unavailable` менее чем за 6 секунд; API liveness и PWA — 200                                                  |
| Восстановление зависимостей                               | Readiness снова 200 после запуска API или снятия паузы БД                                                                                        |
| Ошибка миграции                                           | Неверный пароль миграционной роли даёт ошибку `infra:up`; контейнеры API и gateway не создаются на последующем шаге                              |
| Обычный `infra:down` и повторный `infra:up`               | Контрольная запись в тестовой БД сохранена; readiness восстановлен                                                                               |
| Ограничения gateway                                       | Пользователь `pwa` (UID/GID 10001), read-only root, все capabilities сняты, `no-new-privileges`, нет дополнительных mounts, порт только loopback |
| `npm run check`                                           | PASS: Prettier, ESLint, FSD, типы, 28 существующих тестов                                                                                        |
| OpenSpec                                                  | `openspec validate --all --strict`: 4 изменения прошли                                                                                           |

API-код не менялся; повторный ручной запуск Go-тестов для изменения Caddy/Compose не требовался. Существующий CI продолжает проверять оба приложения и три Docker-сборки.

## Docker context и секреты

Проверка реального контекста через временный `FROM scratch`/`COPY .` выявила прежнее слишком широкое правило `!apps`: оно включало каталог API и локальные Go-бинарники. После добавления исключения `apps/**` перед разрешением PWA повторный экспорт содержит только PWA, общие конфигурации форматтера и `infra/Caddyfile` — около 783 КБ вместо 34 МБ. Каталог API и env-файлы отсутствуют; безопасный env-маркер также исключён. Временная копия контекста и маркер удалены.

Root README сохранил UTF-16 LE BOM. Проверены локальные ссылки, формат изменённых YAML/README/OpenSpec и `git diff --check`. Независимое ревью не выявило блокирующих замечаний.

## Оставленное локальное окружение

После проверки удалены только контейнеры, сеть и volume тестового проекта. Для рабочего локального запуска создан игнорируемый `infra/.env` с разными случайными паролями. Значения не включаются в отчёт, Git или образ.

В момент проверки `task infra:ps` показывает здоровые `postgres`, `api`, `gateway`. PWA доступна на `http://127.0.0.1:8080`, API readiness — на `http://127.0.0.1:8080/api/readyz`. Обычная остановка: `task infra:down`; данные PostgreSQL сохраняются.

Это технический общий запуск. Продуктовые методы и интеграция UI, внешний HTTPS и CD не реализованы этим изменением. Предыдущие ограничения аудита Caddy не объявляются устранёнными; шлюз публикуется только на локальном интерфейсе.

## Переименование команд и аудит

Общие команды переименованы в `task up`, `task check`, `task down`, `task logs`, `task ps`. Проверка `check` теперь открывает и страницу PWA, помимо жизни шлюза и readiness API. Сохраняются отдельные команды `db:*`, `api:*`, `migrate:*` и возможность передать `COMPOSE_ENV`, включая путь с пробелами.

- Полный `task up` прошёл в отдельном проекте `posostavu-task-commands` на новой БД с исправленным образом PostgreSQL. После `task down` и повторного `task up` контрольная запись сохранилась. Неверный пароль мигратора остановил общую команду до запуска API и gateway.
- `task check`, `task ps` и поток логов всех трёх сервисов через `task logs` проверены фактически. Временный процесс просмотра логов остановлен, сервисы при этом не останавливались.
- Незаданные пароли отклоняются `task up COMPOSE_ENV=infra/.env.example` на первом шаге. CLI API и мигратора отклоняют конфигурацию с пустым паролем; существующие тесты `go test ./internal/platform/config` проходят.
- Docker-сборки PWA, API, мигратора и PostgreSQL прошли. Обновлённые API/мигратор и PostgreSQL повторно просканированы; найденная CVE zlib устранена. Остальные результаты и ограничения — в [security-audit.md](security-audit.md).
- Изолированные тестовые контейнеры, сеть, volume и env удалены после проверки принадлежности. Основное окружение обновлено через `task up`, идентификатор кластера PostgreSQL сохранился; все три сервиса здоровы, приложение доступно на `http://127.0.0.1:8080`.
- Документация согласована с новыми командами. README сохранил UTF-16 LE BOM. В отслеживаемых файлах не найдены значения действующих локальных паролей. Пройдены форматирование затронутых YAML/README, `actionlint`, строгая OpenSpec-валидация и `git diff --check`.

На момент завершения локальной проверки изменения были подготовлены в `feature/prd-31-local-stack-audit` без коммита и push. Результаты последующего удалённого CI и проверенный commit SHA фиксируются в PR.
