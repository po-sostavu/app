# Design

## Context

См. [proposal.md](proposal.md). Есть отдельный Compose API/PostgreSQL и контейнер PWA с временным Caddy. Go обслуживает `/livez` и `/readyz`, PWA уже собирается с публичным `/api`; service worker исключает API и кэширует только статическую оболочку.

## Goals / Non-Goals

**Goals:** один локальный origin, один Caddy, последовательный запуск, проверка реальной маршрутизации и сохранения БД.

**Non-Goals:** продуктовая интеграция UI, изменение бизнес-кода, hot reload в контейнере, серверный HTTPS и CD. `npm run dev` остаётся отдельным быстрым режимом работы над интерфейсом.

## Decisions

- `apps/pwa/Dockerfile` остаётся единственной сборкой статики и её сервера. Runtime копирует `infra/Caddyfile`; старый `apps/pwa/Caddyfile` удаляется. Compose называет этот сервис `gateway`. Второй Caddy и отдельный контейнер для неизменяемых статических файлов не нужны.
- Root `.dockerignore` разрешает только `infra/Caddyfile` из каталога инфраструктуры. Env-файлы и остальная инфраструктура не попадают в PWA build context.
- Caddy обслуживает HTTP на 8080, опубликованном как `127.0.0.1:${WEB_PORT:-8080}`. Admin API, автоматический HTTPS и сохранение конфигурации выключены для локального read-only контейнера. UID/GID 10001, capabilities сняты, `no-new-privileges`; Go остаётся отдельным сервисом.
- Матчер `/api` и `/api/*` отделён от fallback PWA. `uri strip_prefix /api` переводит публичный `/api/readyz` во внутренний `/readyz`, точный `/api` — в `/`. Все обработчики статики находятся внутри fallback, поэтому API-путь с `.js` также попадает в Go. Параметры запроса сохраняются, `/apix` не является API-путём.
- Ответы API принудительно `no-store`; ошибки соединения со шлюзом превращаются в короткий неуспешный ответ без внутренних деталей. Dial timeout 3 секунды, ожидание заголовков 15 секунд. API-статусы и JSON не переписываются. Статические cache/security-заголовки сохраняются, CSP и SW менять не требуется.
- `gateway` ждёт healthcheck API, API ждёт PostgreSQL. Healthcheck шлюза проверяет собственный `/healthz`, чтобы отказ API не делал статическую оболочку нездоровой. `task infra:check` отдельно проверяет `/healthz` и `/api/readyz` через шлюз; `--wait` сам по себе не доказывает готовность БД.
- `task infra:up` последовательно проверяет Compose, поднимает БД, вызывает `migrate:up`, запускает `gateway` с зависимостями и выполняет `infra:check`. Ошибка шага останавливает Task. Миграции не добавляются в entrypoint API. `infra:down` сохраняет volume; `infra:ps` и `infra:logs` дают диагностику.
- Порты прямого доступа API и PostgreSQL на loopback сохраняются для разработки Go и SQL-инструментов. Единственный адрес браузерного приложения — шлюз. В OpenAPI добавляется сервер общего локального адреса с `/api`, внутренние paths не меняются.
- Локальный smoke-тест выполняется в изолированном Compose-проекте с временными случайными паролями и отдельным volume. Проверяются маршруты, заголовки, отказ/восстановление API и БД, сохранение контрольной записи после `down/up`. Рабочие данные и чужие контейнеры не затрагиваются.

## Risks / Trade-offs

- Production-сборка не имеет hot reload → для повседневной работы над UI остаётся `npm run dev`; общий запуск проверяет сборку и инфраструктуру.
- Local HTTP и опубликованные loopback-порты не являются production-конфигурацией → HTTPS, окружения и секреты сервера определяются в CD отдельно.
- Существующий образ Caddy имеет ранее описанные ограничения аудита → изменение не объявляет их исправленными и не публикует шлюз в интернет.
- Обновление env не меняет роли в существующей БД → сохраняется инструкция по согласованной смене паролей; обычный запуск не удаляет volume.

## Migration Plan

Добавляется только `WEB_PORT` с необязательным значением 8080. Продуктовых SQL-миграций нет. Существующая БД и команды API сохраняются. Документация, правила PWA и список серверов OpenAPI обновляются вместе с конфигурацией. Откат возвращает предыдущий Compose и Caddyfile; volume не удаляется.
