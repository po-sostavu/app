# Аудит локального запуска

Дата: 07.11.2026. Задача: [PRD-31](https://linear.app/po-sostavu/issue/PRD-31).

Находки Caddy и gosu из этого отчёта исправлены 8 ноября. Повторное сканирование итоговых образов дало 0 записей. Подробности и оставшиеся ограничения — в [текущем отчёте](../../../docs/container-security.md). Результаты ниже сохраняют состояние проверки 7 ноября.

Проверены общий Taskfile, Compose, Caddy, Docker-контексты, конфигурация и права PostgreSQL, HTTP-ошибки и логи, зависимости приложений и итоговые образы Linux amd64. Проверка относится к существующему техническому каркасу. Авторизация, профиль, загрузка фото и внешние OCR/ИИ ещё не реализованы и не проверялись как готовые функции.

## Исправления

1. Примеры env содержали известные непустые пароли, с которыми Compose разрешал создать БД. В `infra/.env.example`, `apps/api/.env.example` и `apps/api/.env.migrate.example` поля паролей теперь пустые. Существующая обязательная валидация отклоняет такую конфигурацию. `task up` останавливается до создания БД. Действующие локальные пароли не менялись
2. В runtime API, мигратора и PostgreSQL обнаружена [CVE-2026-4738](https://www.cve.org/CVERecord?id=CVE-2026-4738): `zlib 1.3.2-r1`. Установлена исправленная `1.4-r0`, указанная в [официальной базе Alpine](https://secdb.alpinelinux.org/v3.24/main.json). API и мигратор получают её из общего runtime. PostgreSQL собирается из прежнего закреплённого официального образа с единственным обновлением zlib. Версия PostgreSQL, entrypoint и volume сохранены. Повторный Trivy-скан всех трёх образов не находит эту CVE

Контекст сборки PostgreSQL исключает все локальные файлы через `.dockerignore`. `init.sh` по-прежнему подключается отдельно только для чтения. Сборка PostgreSQL добавлена в существующую матрицу CI. Прикладные зависимости не добавлены.

## Оставшиеся находки

### Зависимости сборки PWA

[GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) затрагивает deepmerge 4.3.1 через Workbox. Исправленного релиза нет. Предложенный `npm audit` откат `vite-plugin-pwa` до 0.2.1 несовместим с текущим проектом и не применялся. Записи не подавлены. Рабочие npm-зависимости проверяются отдельно.

Текущий шлюз обслуживает статические файлы и фиксированный upstream API внутри сети Compose. Порты хоста опубликованы только на loopback, admin API и автоматический HTTPS выключены. Это ограничивает поверхность атаки, но не доказывает недостижимость всех уязвимых функций. Находки остаются открытыми. Перед внешним развёртыванием их нужно пересмотреть.

### Вспомогательная утилита gosu в образе PostgreSQL

После исправления zlib в образе остаётся 61 запись: 1 CRITICAL, 25 HIGH, 31 MEDIUM, 3 LOW, 1 UNKNOWN. Все относятся к Go-бинарнику `gosu`, который entrypoint использует для смены пользователя перед запуском PostgreSQL. Эти числа не являются числом подтверждённых удалённых уязвимостей самого сервера PostgreSQL.

Дополнительный `govulncheck -mode=binary` нашёл уязвимые символы для [GO-2026-6686](https://pkg.go.dev/vuln/GO-2026-6686): неограниченный разбор passwd/group в `moby/sys/user`. В текущем окружении `/etc/passwd` и `/etc/group` задаются образом, пользовательские файлы туда не монтируются. Ещё 3 находки относятся к импортируемым пакетам, 55 — к модулям без найденных вызовов уязвимых функций. Такой анализ рекомендует [политика безопасности gosu](https://github.com/tianon/gosu/blob/master/SECURITY.md).

[gosu 1.20](https://github.com/tianon/gosu/releases/tag/1.20) исправляет парсер, однако официальный закреплённый образ PostgreSQL пока содержит прежний бинарник. Актуальный digest того же тега совпал с используемым. Релиз gosu также построен старым Go и сам по себе не устраняет все записи stdlib. Бинарник официального образа в этом изменении не заменяется: для единственной находки с уязвимыми символами не выявлен путь поступления недоверенного ввода в текущей конфигурации. Это ограничение оценки, а не признание всех записей ложными.

Аудит не доказывает отсутствие неизвестных уязвимостей. Неустранённые записи сохранены явно. Настройки локального HTTP не предназначены для публикации в интернете.
