# Proposal

## Why

PWA и Go API уже собираются и проверяются в CI, но локально запускаются независимо: `/api` в контейнере PWA отвечает заглушкой. Для подготовки тестового развёртывания нужна одна воспроизводимая локальная точка входа. Изменение относится к инфраструктурной части [PRD-31](https://linear.app/po-sostavu/issue/PRD-31).

## What Changes

- Добавить общий запуск PWA, Go API и PostgreSQL через Docker Compose и Task.
- Перенести конфигурацию единственного Caddy в `infra`: статическая PWA и `/api` на одном origin.
- Выполнять миграции отдельным контейнером до запуска приложений в общей команде.
- Проверять готовность, сохранять локальные данные при остановке и описать команды разработки.
- Использовать общие команды `up`, `check`, `down`, `logs`, `ps`; после аудита исключить готовые пароли из env-примеров и обновить уязвимый системный пакет zlib в контейнерах.

## Capabilities

### New Capabilities

- `local-environment`: общий локальный запуск, маршрутизация, диагностика и остановка приложения без потери БД.

### Modified Capabilities

Нет.

## Impact

Затронуты `infra`, корневой Taskfile, Dockerfile PWA и API, локальная сборка PostgreSQL и её проверка в CI, Docker ignore, серверы OpenAPI-контракта и документация. Используются существующие образы и зависимости. Продуктовые методы, интеграция UI с пользовательскими сценариями, авторизация, OCR/ИИ, HTTPS для внешнего сервера и CD не входят в изменение. Наличие общего адреса не означает реализацию профиля или анализа фото.
