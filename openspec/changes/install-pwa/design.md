# Design

## Context

Мотивация и границы — в [proposal.md](proposal.md). В `vite.config.ts` уже заданы manifest с `id: '/'`, `start_url: '/'`, `display: 'standalone'`, иконки и service worker. `AppLayout` содержит компактную шапку с названием. `app/pwa/PwaStatus` управляет сетью и обновлением, установки в интерфейсе пока нет.

## Goals / Non-Goals

**Goals:**

- Отделить состояние установки от представления и проверить значимые переходы в существующем Vitest без DOM-библиотек
- Сохранить программную установку в доступных браузерах и ручной путь в остальных
- Скрывать действие по подтверждённым сигналам браузера, корректно обрабатывать асинхронные ответы и повторные нажатия

**Non-Goals:**

- Собственный установщик, публикация в магазинах и гарантированное определение установки во всех браузерах
- Изменение API, БД, серверного окружения, политики кэширования и пользовательского управления обновлением

## Decisions

### FSD и компоненты

Срез `features/install-app` содержит модель состояния и интерфейс на имеющихся Mantine Button и Modal. `app/layouts` использует его публичный API. Это действие пользователя, поэтому его модель не переносится в `shared` или экран анализа. Обработку сети и обновления оставляем в `app/pwa`.

Модель предоставляет стабильный снимок и подписку для `useSyncExternalStore`. Слушатели установки подключаются достаточно рано, чтобы не терять разрешение браузера до появления кнопки. Результаты асинхронной проверки не должны отменять более позднее подтверждение установки. Один системный запрос обрабатывается один раз, параллельные нажатия блокируются. При отмене или ошибке использованное разрешение удаляется. Новое разрешение браузера снова делает системный путь доступным.

### Браузерные сигналы

Для запуска используется `beforeinstallprompt`, только внутри обработчика нажатия. Завершение определяется через `appinstalled`, режим отдельного окна — через `display-mode` и `navigator.standalone` на iOS. Один ответ `userChoice: accepted` не заменяет подтверждение фактической установки.

Дополнительно используем `navigator.getInstalledRelatedApps`, если метод доступен. В manifest добавляется ссылка на собственный webapp с `url: '/manifest.webmanifest'` без жёстко заданного домена. Скрытие разрешено только при совпадении типа `webapp` и абсолютного URL собственного manifest. Ошибка или пустой ответ не скрывают кнопку и не блокируют интерфейс.

Такая self-reference пригодна для проверки на поддерживаемом Android. Desktop-проверке нужен абсолютный related `id`, поэтому она не гарантируется: ради неё не вводим отдельную доменную конфигурацию. В обычной вкладке Safari и других браузеров без нужного API установленность может оставаться неизвестной. Постоянный `localStorage`-флаг отклонён, потому что он переживает удаление PWA и может ошибочно скрыть установку.

### Ручная установка и доступность

При отсутствии системного вызова кнопка открывает инструкцию. Платформа выбирает текст, но не служит доказательством поддержки программной установки. Для iOS/iPadOS описывается меню «Поделиться» и добавление на главный экран, Safari предлагается как запасной вариант. Для Safari macOS — добавление в Dock. Для Android и остальных desktop-браузеров — доступное действие установки браузера и совместимый запасной вариант при его отсутствии.

Диалог использует штатные управление фокусом и Escape Mantine. Кнопка сохраняет текстовое имя и область нажатия не менее 44 px, шапка проверяется на 320 px. Ошибка установки не закрывает приложение и не сбрасывает текущий маршрут.

## Risks / Trade-offs

- Браузеры не предоставляют универсальную проверку установленности → скрывать по доступным положительным сигналам, описать ограничения обычной вкладки в документации
- Разрешение установки одноразовое и может появиться позже → хранить только актуальное событие и не повторять использованное
- Проверка установленности может завершиться после другого события → не позволять старому ответу вернуть кнопку после установки
- Тексты меню отличаются по версиям браузера → давать короткую инструкцию с запасным способом и проверять её по официальным источникам
- Эмуляция браузерных событий не доказывает реальную установку на каждом устройстве → отдельно записать, какие проверки выполнены в браузере, а какие только тестами модели

## Migration Plan

Миграций данных и изменений OpenAPI нет. Обновить `docs/architecture.md`, `apps/pwa/AGENTS.md` и README PWA вместе с реализацией. Сохранить существующие идентификатор, scope и стартовый адрес manifest, чтобы выпущенная PWA продолжила обновляться.

Провести проверки PWA и CI, затем выпуск `0.2.0` по `feature → develop → release/0.2.0 → main`. CD публикует проверенные образы, выкладка проходит действующее подтверждение Environment production. Совместимость с прежним API и БД сохраняется. Откат приложения использует прежний комплект, не откатывает БД и сохраняет статику уже полученной PWA.
