# Design

## Context

CI собирает четыре образа на отдельных runners. Сервер использует существующий Traefik и принудительную SSH-команду. Адреса и секреты production уже настроены пользователем. Работа на VPS запрещена в рамках этого изменения.

## Goals / Non-Goals

Подготовить проверяемую доставку для текущего каркаса. Продуктовые API, мониторинг бизнес-сценариев, настройка внешнего хранилища резервных копий и первый деплой выполняются отдельно.

## Decisions

- Docker save с gzip level 1: локальный замер дал 161 158 745 байт, около 154 МиБ. Наибольший архив PostgreSQL — около 114 МиБ. Повторная сборка не гарантирует тот же результат, поэтому CI передаёт готовые образы. PR сохраняет артефакты на один день для интеграционного теста, main на семь дней для CD. Время передачи измеряется в CI
- Публичные GHCR-пакеты не требуют токена на VPS. Новые пакеты GitHub первоначально создаёт приватными, поэтому перед включением деплоя администратор меняет видимость и проверяет анонимное скачивание. Workflow не меняет права пакетов
- Два workflow: CI и CD. CD проверяет upstream event, repository, branch, conclusion, SHA и номер попытки. Флаги `CD_PUBLISH_ENABLED` и `CD_DEPLOY_ENABLED` по умолчанию выключены. Публикация имеет packages:write, SSH доступен только job с Environment production
- Go standard library для проверки JSON, файлов, блокировки, атомарного состояния и запуска процессов без shell. Отдельный модуль tools/delivery не содержит внешних зависимостей. Root устанавливает собранный для Linux бинарник и фиксированные конфигурации. SSH не передаёт произвольных команд или путей. Незавершённая операция блокирует новую до проверки администратором
- Отдельные Compose для общей БД и каждого цвета. PostgreSQL закрепляется при первой установке. Обновление её образа — отдельное обслуживание, а не побочный эффект выпуска PWA
- Публичный маршрут переключается атомарной заменой отдельного файла Traefik. Caddy обслуживает HTTP:8080 и API своего цвета, не управляет HTTPS
- Общий каталог содержит только файлы `assets/` и `workbox-*.js`. Извлечение из образа запрещает ссылки и выход за каталог. Совпавший путь с другим содержимым блокирует выпуск. Автоматического удаления старых файлов нет
- Резервная копия перед миграцией создаётся через pg_dump и проверяется pg_restore --list. Это не заменяет пробное восстановление и копию вне VPS. Перед первым включением CD нужен подтверждённый регламент восстановления
- Совместимость отката подтверждается в описании выпуска до выкладки. В текущем каркасе интеграционные проверки покрывают PWA, health endpoints, миграции, данные и переключение. При появлении продуктовых методов набор сценариев расширяется

## Risks / Trade-offs

- Один VPS и общая БД остаются единой точкой отказа
- Артефакты имеют срок хранения. Если они истекли, публикация прекращается, автоматической пересборки нет
- Находки аудита Caddy и gosu устранены. Версии сборок, результаты повторного сканирования и ограничения описаны в [проверке контейнеров](../../../docs/container-security.md)
- Неизвестные имя resolver, entrypoints и путь host-каталога Traefik остаются обязательными параметрами установки. Их нельзя угадать по данным репозитория
- История статических файлов занимает диск. Свободное место проверяется перед выкладкой, очистка требует отдельного решения о поддержке старых PWA

## Migration Plan

Проверить PR и CI, затем отдельно установить серверные файлы и секреты, настроить резервное копирование, сверить выпуск с результатами проверки контейнеров и проверить Traefik. После релиза в main включить только публикацию, сделать пакеты публичными и проверить digest. Деплой включать после этих проверок и подтверждать через production. Откат приложения не запускает миграции down.
