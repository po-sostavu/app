# Spec Delta

## Purpose

Доставлять проверенный выпуск приложения без пересборки, сохраняя данные и возможность безопасного переключения между версиями.

## ADDED Requirements

### Requirement: Publish tested images
Система SHALL публиковать четыре образа из успешного push CI main того же репозитория без пересборки. Публикация и деплой выключены до отдельного включения.

#### Scenario: Untrusted or incomplete run
- **WHEN** источник — PR, develop, другой репозиторий, неуспешный CI или неполный набор артефактов
- **THEN** публикация запрещена

#### Scenario: Existing release tag
- **WHEN** тег коммита уже указывает на другой образ
- **THEN** публикация завершается ошибкой без перезаписи тега

### Requirement: Restricted deployment
Система SHALL запрашивать подтверждение production перед SSH и принимать только проверяемое описание выпуска с digest четырёх разрешённых образов. Секреты остаются на сервере и в Environment.

#### Scenario: Invalid input
- **WHEN** запрос содержит команду, неизвестное поле, неверный digest или слишком большой документ
- **THEN** обработчик отклоняет запрос до изменения контейнеров

### Requirement: Safe color switch
Система SHALL сериализовать выкладки, проверять ресурсы, резервную копию, миграции и готовность неактивного комплекта до переключения. PostgreSQL общая и не откатывается вместе с приложением.

#### Scenario: Candidate fails
- **WHEN** миграция или проверка нового комплекта завершается ошибкой
- **THEN** активный маршрут сохраняется, миграции down не выполняются

#### Scenario: Public check fails
- **WHEN** после переключения публичная проверка не проходит
- **THEN** прежний маршрут восстанавливается при заранее подтверждённой совместимости отката

#### Scenario: Repeated request
- **WHEN** повторно поступает уже завершённый выпуск
- **THEN** обработчик сообщает текущий результат без повторной миграции

### Requirement: Preserve supported clients
Система SHALL сохранять файлы с хешами поддерживаемых PWA независимо от цвета. Подтверждение выпуска включает совместимость миграций и уже обновившихся PWA с сервером для отката.

#### Scenario: Application rollback
- **WHEN** предыдущий комплект снова принимает трафик
- **THEN** файлы обоих выпусков доступны, данные PostgreSQL сохранены

### Requirement: Explicit test deployment
Система SHALL требовать подтверждённое восстановление для рабочего режима и при отсутствии режима в конфигурации. Только явный `mode: test` SHALL разрешать выкладку без `recovery_verified` для стенда с заменяемыми тестовыми данными. Флаг enabled, локальная копия перед миграцией и остальные проверки остаются обязательными.

#### Scenario: Production recovery not verified
- **WHEN** mode отсутствует или равен production, а recovery_verified равен false
- **THEN** запрос отклоняется до операций Docker

#### Scenario: Explicit test mode
- **WHEN** mode равен test, enabled равен true и остальные проверки пройдены
- **THEN** отсутствие подтверждения восстановления не блокирует выкладку, копия перед миграцией выполняется

#### Scenario: Unknown or disabled mode
- **WHEN** mode неизвестен или enabled равен false
- **THEN** запрос отклоняется до операций Docker независимо от recovery_verified
