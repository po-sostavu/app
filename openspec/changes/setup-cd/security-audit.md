# Проверка доставки выпуска

8 ноября 2026 года. Область: новые workflow, production Compose, обработчик SSH и передача образов. VPS и GHCR не изменялись.

## Проверено

- CD принимает только успешный push CI main своего репозитория, использует SHA и попытку исходного запуска
- Флаги публикации и выкладки выключены по умолчанию. Environment production стоит только на job deploy
- CI получает contents:read, публикация отдельно получает packages:write. Прямого SSH-доступа к Docker нет
- Actions закреплены SHA. Образы передаются без пересборки, сверяются по checksum, image ID, платформе и OCI labels. Существующий тег с другим образом не перезаписывается
- SSH использует известный host key, BatchMode, отдельный временный ключ и принудительную серверную команду. Строки shell не принимаются серверным обработчиком
- Входной JSON ограничен по размеру и времени чтения. Проверяются поля, SHA, digest, run ID и подтверждённая совместимость отката
- Серверные файлы и их родительские каталоги должны принадлежать root и быть закрыты на запись другим пользователям. Секреты требуют 0600, разных паролей ролей и совпадения пароля приложения с соответствующей ролью
- API, БД и мигратор не публикуют host-порты. Цвета имеют отдельные сети. Контейнеры ограничены по ресурсам, root filesystem доступна только для чтения
- Общая БД не пересоздаётся при выпуске приложения. Перед миграцией проверяются свободное место и архив pg_dump. Down-миграции отсутствуют в обработчике
- Выкладки сериализованы. Незавершённый журнал блокирует повтор. Ошибка нового комплекта сохраняет активный маршрут, ошибка публичной проверки или записи состояния возвращает прежний маршрут
- Архив статики не допускает абсолютные пути, выход через `..`, ссылки, специальные файлы и превышение лимитов. Существующий immutable-файл с другим содержимым не перезаписывается
- Тесты в Linux покрывают некорректный ввод, повреждённый артефакт, конфликт тега, повторную публикацию, сохранение статики, миграционные и сетевые ошибки, блокировку, идемпотентность и сбой записи состояния
- Инструменты доставки используют Go standard library без внешних зависимостей. Локальные gofmt, линтер проекта и тесты прошли, govulncheck не обнаружил уязвимостей. [CI версии на Go](https://github.com/po-sostavu/app/actions/runs/42424274361) прошёл все восемь заданий, включая race detector и изолированный стенд

## Ограничения перед включением

Реальная публикация GHCR, forced command на VPS, production-секреты, ACME и публичный HTTPS в этой работе не проверялись. Изолированный CI проверяет переключение file provider через HTTP на loopback. Совместимость двух версий продукта пока ограничена текущим каркасом без продуктовых методов.

`pg_restore --list` проверяет структуру архива, но не заменяет восстановление. Копия вне VPS и политика хранения должны быть настроены до включения `recovery_verified`. Приложение само их не создаёт.

Образы Caddy и PostgreSQL в этом изменении не обновлялись. Открытые находки предыдущего [аудита контейнеров](../local-stack/security-audit.md) остаются условием перед публичной выкладкой. Этот аудит не объявляет их исправленными. Старый PostgreSQL других проектов требует отдельной проверки публичного доступа.

Публичность новых GHCR-пакетов администратор задаёт после первой разрешённой публикации. Deploy проверяет анонимное чтение всех digest до SSH. Изменение видимости и первый выпуск не выполнялись.
