# Proposal

## Why

Для дальнейшей разработки нужен запускаемый Go API с проверяемой конфигурацией, управляемым завершением и воспроизводимой работой с PostgreSQL. Изменение связано с [PRD-29](https://linear.app/po-sostavu/issue/PRD-29): перевод согласованной архитектуры в технический каркас, без реализации продуктовых сценариев.

## What Changes

- Добавить Go module, HTTP-сервер Fiber v2, конфигурацию окружения, структурированные логи, проверки жизни и готовности, корректное завершение.
- Закрепить устройство модулей Clean Architecture с DDD на стороне команд и SQL-проекциями в DTO на стороне запросов. Не создавать выдуманные бизнес-правила и пустые реализации.
- Добавить пул PostgreSQL через sqlx, отдельную команду миграций golang-migrate и привычные команды создания, применения, просмотра версии и отката.
- Подготовить локальный Compose для API и PostgreSQL, Dockerfile, gofmt, golangci-lint v2, проверки тестов и уязвимостей.
- Описать реальные HTTP-методы в OpenAPI; обновить README, архитектуру и инструкции.

## Capabilities

### New Capabilities

- `api-runtime`: конфигурация, технические HTTP-методы, обработка отказов и жизненный цикл API.
- `database-migrations`: независимое версионирование и управление схемой PostgreSQL.

### Modified Capabilities

Нет.

## Impact

Затронуты `apps/api`, `infra`, `contracts/openapi.yaml`, документация и общие команды. Зависимости: согласованный серверный стек, драйвер pgx и средства локальной разработки. PWA не подключается к API; CI/CD, общий Caddy, OCR/ИИ, авторизация, продуктовые endpoints и таблицы остаются за границами изменения. Пользователь поручил реализацию и небольшие коммиты в отдельной ветке; push и merge в эту задачу не входят.
