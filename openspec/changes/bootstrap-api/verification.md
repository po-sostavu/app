# Проверка каркаса API

Дата: 07.11.2026. Изменение: `bootstrap-api`, PRD-29.

## Проверки кода

| Проверка                      | Результат                                                                                            |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| `task api:check`              | Формат gofmt, golangci-lint, тесты и сборка прошли на Windows и Linux                                |
| `task api:test:race`          | Все тесты API прошли в Linux amd64 с Go 1.27.3 и C-компилятором                                      |
| `task api:audit`              | govulncheck не обнаружил известных уязвимостей приложения                                            |
| `go mod verify` из `apps/api` | Контрольные суммы модулей подтверждены                                                               |
| OpenSpec                      | `openspec validate --all --strict`: оба изменения валидны                                            |
| OpenAPI                       | Проверены структура OAS 3.1, локальные ссылки, методы, коды ошибок и примеры ответов                 |
| Документация                  | Команды, параметры окружения и ссылки сверены с кодом; новая Mermaid-схема отрендерена и просмотрена |

Linux-проверки выполнялись в контейнере `golang:1.27.3-bookworm`, с Task 3.54.0. Исходники подключались только на чтение, проверки работали с временной копией. PowerShell и Make для команд проекта не требуются. Инструменты разработки находятся в отдельном Go module и не включаются в runtime-зависимости API.

Тесты проверяют ошибки конфигурации и отсутствие её значений в диагностике, приоритет окружения, тайм-аут проверки БД, безопасные HTTP-ошибки, серверный request ID, раннюю отмену запуска, штатное завершение и отмену операций по deadline. Миграционные тесты проверяют недопустимые имена, неполные пары и повторные версии, сохранность существующих файлов, подтверждение опасных команд и безопасную диагностику.

Первичная проверка зависимостей выявила уязвимый транзитивный пакет. Выполнено совместимое обновление fasthttp/compress при сохранении Fiber v2; повторные тесты, линтинг и govulncheck прошли. Результат аудита относится к известным уязвимостям Go-кода на дату проверки, не является полной оценкой будущего production-развёртывания.

## Локальная инфраструктура

Проверен отдельный Compose project с новой тестовой PostgreSQL 18.6. Реальные пользовательские данные не использовались.

- Оба Docker target, `api` и `migrate`, собраны; `task api:up` и `task migrate:version` выполнены с отдельным env-файлом.
- `GET /livez` и `/readyz` возвращают 200; неизвестный маршрут — 404; превышение лимита тела — 413.
- Проверены `X-Request-ID`, его независимость от клиентского значения и `Cache-Control: no-store`.
- При приостановленной PostgreSQL `/readyz` возвращает 503 в пределах query timeout, `/livez` продолжает отвечать 200. После возобновления БД готовность восстанавливается без перезапуска API.
- Логи не содержат переданный в неизвестном URL контрольный маркер. API работает с UID 10001.
- SIGTERM завершает API с кодом 0; в логах подтверждено окончание shutdown.
- Рабочая роль не имеет административных прав, прав создания таблиц или чтения `schema_migrations`. Явный GRANT на тестовую таблицу разрешает необходимую работу с её данными.

## Миграции

Миграционный контейнер успешно обработал пустой каталог. На отдельной тестовой БД через Go-команду проверены:

1. Создание последовательной пары и применение `up`.
2. Повторный `up` без повторного выполнения и просмотр версии.
3. Откат одного шага и последующее применение.
4. Ошибка SQL внутри транзакции: тестовая таблица не сохраняется, версия становится dirty, повторный `up` отклоняется.
5. `force` без подтверждения отклоняется. После проверки фактической схемы явный `force` восстанавливает метаданные, исправленная тестовая миграция применяется.
6. Откат обеих тестовых миграций возвращает версию в `none`; продуктовых таблиц в репозитории нет.

Продуктовые транзакции, авторизация, распределённая идемпотентность, OCR/ИИ, интеграция PWA, общий шлюз и CI/CD этим изменением не реализованы и не проверялись. Для них потребуются соответствующие прикладные сценарии и проверки.

После проверок удалены созданные тестом контейнеры, volume, временные SQL-файлы и конфигурация с тестовыми паролями. Рабочие данные других окружений не затрагивались.
