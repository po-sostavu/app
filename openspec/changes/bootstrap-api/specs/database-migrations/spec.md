# Spec Delta

## Purpose

Разработчик должен управлять версиями PostgreSQL отдельными воспроизводимыми командами, независимо от запуска экземпляров API.

## ADDED Requirements

### Requirement: Создание и применение миграций

Инструменты проекта MUST создавать последовательную пару `.up.sql`/`.down.sql`, применять новые миграции и показывать текущую версию и dirty-состояние. Повторное применение без новых миграций MUST завершаться успешно.

#### Scenario: Повторное применение

- **WHEN** разработчик запускает up второй раз с тем же каталогом SQL
- **THEN** уже применённые изменения не выполняются повторно и команда завершается успешно

#### Scenario: Каркас без продуктовых таблиц

- **WHEN** база доступна, а каталог не содержит миграций
- **THEN** up завершается без создания выдуманных продуктовых таблиц и сообщает об отсутствии миграций

### Requirement: Контролируемый откат и восстановление

Обычная команда down MUST откатывать ровно один шаг. Полный откат и изменение dirty-версии MUST требовать явных отдельных действий. Неуспешный SQL MUST приводить к ненулевому коду команды, а dirty-состояние MUST NOT автоматически сбрасываться.

#### Scenario: Ошибка SQL

- **WHEN** миграция завершилась ошибкой
- **THEN** команда завершается неуспешно, дальнейший up не выдаётся за успешный, а оператор может проверить dirty-версию и исправить состояние по инструкции

### Requirement: Изоляция миграций от API

Миграции MUST запускаться отдельно от HTTP API, с отдельными правами изменения схемы. API MUST использовать рабочую роль без административных прав. Пароль подключения MUST NOT передаваться в аргументах миграционной команды или попадать в её вывод.

#### Scenario: Запуск второго экземпляра

- **WHEN** запускается дополнительный экземпляр API
- **THEN** он не запускает миграции и не получает миграционные права
